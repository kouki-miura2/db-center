A tool that centralizes database design to improve development efficiency.

## 総論

### 目的

ITエンジニアが複数プロダクトのデータベース設計を一元管理するツール。  
"Googleでログイン" により認証されたユーザーはプロダクトを作成または参加する。  
プロダクトには複数のデータベースを登録できる。  
データベースはバージョン1・編集中状態で開始し、設計を確定するとバージョン1・確定状態になる。  
データベース設計はバージョン間の差分出力ができるため、バージョンNからMまでの差分スクリプトを出力できる。  
プロダクトにデータベース接続情報が設定されている場合、直接ビルドまたは差分スクリプトによるマイグレーションができる。

### 利用イメージ

- Googleでログイン
  - 利用規約、プライバシーポリシーに同意したあと、Googleでログインすることにより使用開始
- プロダクト登録
  - プロダクトを登録すると、オーナーとなりマネージャーとメンバーを招待できる
  - プロダクトにターゲットを設定する e.g. PostgreSQL18
  - プロダクトにデータベース接続情報を設定する
- プロダクトに参加
  - 招待されたプロダクトにマネージャーまたはメンバーとして参加できる
- データベース作成
  - プロダクトにデータベースを作成する
  - データベースはバージョン1・編集中状態
- データベース設計
  - データベースにスキーマを追加・編集・削除する
  - スキーマにテーブルを追加・編集・削除する
  - テーブルにカラムを追加・編集・削除する
  - テーブル・カラムに制約を追加・編集・削除する
  - テーブルのサイズ設計（時間単位あたりに何件のレコードが登録・編集・削除されるかの見積もり）をする
  - テーブルにインデックスを追加・編集・削除する
  - スキーマにシーケンスを追加・編集・削除する
  - スキーマにビューを追加・編集・削除する
  - バージョンを仮確定する
  - バージョンを確定する
  - テーブル定義書をPDFまたはMarkdownファイルで出力する
  - 新しいバージョンを作成する
- データベースをビルドする
  - 仮確定バージョンまたは確定バージョンを指定してDDL(DataDefinitionLanguage)スクリプトを出力する
  - データベース接続情報が設定されている場合、仮確定バージョンまたは確定バージョンを指定してデータベースを自動ビルドする
- データベースをマイグレーションする
  - 更新前後の仮確定バージョンまたは確定バージョンを指定して更新用DDLスクリプトを出力する
  - データベース接続情報が設定されている場合、仮確定バージョンまたは確定バージョンの更新後のバージョンを指定してデータベースを自動マイグレーションする

### 提供形態

- PWAとして提供する。主な利用環境はPC、タブレット、スマホとする。
- インターネット経由で利用できる公開アプリとする。
- 日本国内向けのサービスとする。日付の判定と日時の表示はAsia/Tokyoとする（コード上は `packages/utils/src/date/zone.ts` の `TIME_ZONE_OFFSET_MINUTES`）。

### データの単位

- データは「プロダクト」単位で管理する。ユーザーは複数のプロダクトに参加できる。
- 1プロダクトに参加できるユーザーは、オーナー・マネージャー・メンバー合わせて10名までとする（「リミット値」参照）。
- 1ユーザーが参加できるプロダクトは20件までとする（「リミット値」参照）。

### 用語

| 用語               | 意味                                                                                                                         |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| プロダクト         | データを管理する単位。データベース・ターゲット・データベース接続情報をまとめる。                                             |
| ロール             | プロダクトでのユーザーの立場。オーナー（プロダクトを作成したユーザー。1プロダクトに1人）・マネージャー・メンバーのいずれか。 |
| ターゲット         | プロダクトのデータベースを構築するデータベース製品とそのバージョン（例: PostgreSQL 18）。                                    |
| データベース       | プロダクトに登録する設計の単位。複数のバージョンを持つ。                                                                     |
| 接続先データベース | データベース接続情報で接続する、実際に稼働しているデータベース。                                                             |
| サイズ設計         | テーブルごとの、時間単位あたりに登録・編集・削除されるレコード件数の見積もり。                                               |
| バージョン         | データベースの設計の版。1から始まる連番で、編集中・仮確定・確定のいずれかの状態を持つ。確定したバージョンは変更できない。    |
| 仮確定             | 設計を一旦固定し、DDLスクリプトの出力やビルド・マイグレーションに使えるようにしたバージョンの状態。                          |
| 差分スクリプト     | 2つのバージョン（更新前・更新後）の差分から、更新前の構成を更新後の構成に変更するために出力するDDLスクリプト。               |

### 共通ルール

<!-- 複数の機能にまたがるルール。各論では繰り返さず、ここを参照する。 -->

- 入力
  - 文字数・件数の上限は「リミット値」参照。上限は画面とAPIの両方でチェックする。
  - 文字数は見た目の1文字を1文字と数える（全角・半角・絵文字とも1文字）。
  - 一意: プロダクト名は自分がオーナーのプロダクト内、データベース名はプロダクト内（どちらも削除状態のものを除く。削除したものと同じ名前で作り直せる）、オブジェクトの物理名は同じバージョン・同じスキーマ内（削除済みを除く）で重複できない。物理名の文字種・予約語はターゲットの規則に従う。
- 画面
  - <全画面共通の表示>
  - アプリの更新: 新しいバージョンが公開されると、画面下部に「新しいバージョンがあります」のスナックバー（濃いグレー、「後で」「更新」ボタン付き）を閉じるまで表示する。「更新」で新しいバージョンに切り替えて再読み込みする。「後で」で閉じた場合は、次にアプリを開いたときに再び表示する。入力中の内容を失わないよう、自動では切り替えない。ほかのスナックバーの表示中は隠れる。
  - 新しいバージョンの確認は、アプリを開いたとき・アプリが前面に戻ったとき・1時間ごとに行う（ホーム画面のアプリはバックグラウンドから戻るだけで、ページを読み込み直さないことが多いため）。
- 日付・日時の表示
  - 年を含める場合は `2026/09/29`（日時は `2026/09/29 10:21`）とする。
  - 年を表示しない場合は `9/29` とする。
- 同意
  - Google でログインしたあと、未登録のユーザーには同意画面を表示する。利用規約・プライバシーポリシーへの同意とユーザー名の入力が済んだときに、ユーザーを登録する（同意はサーバーに記録する）。
  - 利用規約・プライバシーポリシーを改定したら版を上げる。同意した版が古いユーザーには、次のログイン時に同意画面を表示し、同意するまで使えなくする。
- 削除
  - プロダクト・データベース・オブジェクト（スキーマ・テーブル・ビュー・シーケンス）の削除は2回確認する。2回目は、削除する対象の名前（プロダクト名・データベース名・オブジェクトの物理名）の入力が一致したときだけ削除できる。
  - プロダクトを削除すると、配下のデータとともに削除状態にし、どの画面・API からも参照できなくする。削除状態のまま保持期間（「リミット値」参照）が過ぎたら完全に削除する。画面から復元はできない。
- 同時更新
  - 後から保存した人をエラーにする（楽観ロック）。画面を開いた時点の更新日時を保存時に送り、保存先の更新日時と一致しなければ保存せず、「他のユーザーが更新しました。再読み込みしてください」と表示する。
  - 対象は更新日時を持つすべてのデータ（プロダクト、データベース接続情報、データベース、バージョン、オブジェクト）。設計の編集はオブジェクト（テーブルなど）単位で判定する。
- オフライン
  - 通信できないときは、最後に表示したデータを読み取り専用で表示し、「オフラインです」と表示する。登録・変更・削除・出力・ビルド・マイグレーションはできない。
  - 表示したデータは端末に保存する（「参照 > データの取得とキャッシュ」参照）。ログアウト・退会したときは端末から消す。データベース接続情報のパスワードは API が返さないため、端末にも保存されない。

### 対象外

<!-- 提供しない機能を明記し、スコープの膨張を防ぐ。 -->

次の機能は提供しない。

- SQLite 3 の自動ビルド・自動マイグレーション（スクリプトの出力だけを提供する）
- インターネットから接続できないデータベースへの自動ビルド・自動マイグレーション
- データ損失・ドリフトを含む自動マイグレーション（差分スクリプトを出力して利用者が実行する）
- サイズ設計の推奨・注意の表示（見積もり結果の表示だけを提供する）
- 招待の取り消し（有効期限で無効になる）
- 削除したプロダクト・データベースの画面からの復元

### Googleでログイン

  - プライバシーポリシーボタン。押下時にプライバシーポリシーを表示。この画面に戻れること

#### 登録・変更・削除

- Googleアカウントの初回ログイン時、ユーザーが登録される
- ユーザー登録済みのGoogleアカウントの場合、最終ログイン日時が更新される
- ログイン状態
  - Google の ID トークンはログイン時だけ検証し、アプリ独自のセッションを発行する。セッションは HttpOnly・Secure・SameSite=Lax の Cookie で保持し、有効期間は「リミット値」参照。
  - ログアウトすると、そのセッションを削除する。
- 退会
  - ユーザーは自分で退会できる。オーナーのプロダクトがある場合は、先にそのプロダクトを削除しないと退会できない。
  - 退会すると、参加しているプロダクトから退出し、Google アカウントの ID・メールアドレスを消し、すべてのセッションを削除する。ユーザー名は「退会したユーザー」と表示する。
  - 退会したユーザーが作った設計・実行履歴は残す。
  - 同じ Google アカウントで再びログインした場合は、新しいユーザーとして登録する。

### プロダクト管理

- プロダクト登録
  - プロダクト一覧画面で、プロダクト追加ボタンを押下するとプロダクト登録画面に遷移する
  - プロダクト名、ターゲット、データベース接続情報を登録する

- プロダクト編集
  - プロダクト一覧画面で、プロダクト編集ボタン押下、プロダクト選択するとプロダクト編集画面に遷移する
  - プロダクト編集画面でプロダクト名、データベース接続情報を編集できる
  - プロダクト編集画面でプロダクトを削除できる

- プロダクトに参加
  - 招待する側
    - オーナーまたはマネージャーがプロダクトを選択した状態で「招待する」ボタンを押すとユーザー招待画面に遷移する
    - ユーザー招待画面で、招待するユーザーのGoogleアカウントとユーザー種別（マネージャー or メンバー）を複数を入力したあと、招待コードを表示するボタン押下で8桁のパスコードを表示する（招待したユーザーは仮登録）
  - 参加する側
    - プロダクト一覧画面で、プロダクト参加ボタンを押下するとパスコード入力画面に遷移する
    - 招待された正しいパスコードを入力して参加するボタンを押下すると参加完了になる

    - プロダクト名、プロダクト登録日、プロダクト参加日、ユーザー種別（オーナー、マネージャー、メンバー）
  - プロダクト追加ボタン
  - プロダクト参加ボタン
- ユーザー招待画面
  - Googleアカウント・ユーザー種別入力　※複数
  - 招待コードを表示するボタン
- パスコード入力画面
  - 8桁パスコード
  - 参加するボタン
- 操作
  - プロダクト登録画面の登録するボタン押下でプロダクトを登録する
  - プロダクト編集画面の保存するボタン押下でプロダクトの編集内容を保存する
  - プロダクト編集画面の削除するボタン押下で、2回確認（2回目はプロダクト名の文字列入力が一致した場合）プロダクトを削除する
  - プロダクト一覧画面のプロダクトを選択するとデータベース一覧画面に遷移する
  - プロダクト追加ボタンを押下するとプロダクト登録画面に遷移する
  - プロダクトを選択した状態（データベース一覧画面等）で「招待する」ボタンを押すとユーザー招待画面に遷移する
  - ユーザー招待画面の招待コードを表示するボタン押下で8桁のパスコードを表示する
  - パスコード入力画面で8桁パスコード入力すると参加するボタンが押下可能になる
  - 参加するボタン押下で、正しいパスコードが入力されている場合、プロダクトに参加完了する

#### 一覧

- プロダクト一覧の並び順はプロダクト名順とする。
- 参加者の並び順は、オーナー → マネージャー → メンバー → 仮登録の順、同じロール内はユーザー名順（仮登録はメールアドレス順）とする。
- データベース接続情報の並び順は登録順とし、並べ替えできる。

#### 登録・変更・削除

- 削除
  - プロダクト内のすべてのデータが削除状態となる（「共通ルール > 削除」参照）
- 招待
  - 同時に入力したユーザーには、同じ8桁のパスコードを発行する。パスコードは英数字で、大文字・小文字を区別しない。
  - 招待の有効期間は「リミット値」参照。期限が切れた招待では参加できない（招待し直す）。
  - 有効期間中は、ユーザー招待画面でパスコードを再表示できる。
  - すでに参加完了しているユーザーは招待できない（エラー）。
  - 仮登録中のユーザーを招待すると、新しいパスコードで招待し直し、古い招待は無効にする。
  - 参加完了のユーザーと有効期間中の仮登録のユーザーの合計が、1プロダクトの参加者の上限（「リミット値」参照）を超える招待はできない（エラー）。
  - 招待は取り消さない。参加されなかった招待は有効期限で無効になる。
- ロールの変更・オーナーの譲渡
  - 参加者のロールをマネージャー ⇔ メンバーで変更できる（変更できるロールは「権限」参照）。
  - オーナーは、参加完了している他の参加者にオーナーを譲渡できる。譲渡すると、譲渡したユーザーはマネージャーになる。確認ダイアログを表示する。譲渡先のユーザーがオーナーのプロダクトに同じ名前のものがある場合は、譲渡できない（エラー）。
- 除外・退出
  - オーナー・マネージャーは、権限のある参加者をプロダクトから除外できる（「権限」参照）。マネージャー・メンバーは自分でプロダクトから退出できる。どちらも確認ダイアログを表示する。
  - 除外・退出したユーザーが作った設計・実行履歴は残し、更新者・実行者としての名前も表示する。
- 参加
  - 入力したパスコードと、ログイン中のユーザーの Google アカウントのメールアドレスが、どちらも有効期間中の招待と一致したときだけ参加できる。一致しない場合は「パスコードが正しくないか、このアカウント宛ての招待ではありません」と表示する。
  - パスコードの入力に失敗した回数をユーザーごとに数え、上限（「リミット値」参照）に達したら、しばらく入力できなくする。
  - 参加するユーザーの参加プロダクト数が上限（「リミット値」参照）に達している場合は参加できない。

### データベース

- プロダクトにデータベースを作成し、バージョンごとに設計する。
- バージョンは編集中 → 仮確定 → 確定と進み、確定したバージョンから新しいバージョンを作る。

#### 項目

| 項目           | 備考                                                                                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------------------- |
| データベース名 | 必須。英小文字で始まり、英小文字・数字・`_` のみ、63文字以内。プロダクト内で重複不可（削除状態のデータベースを除く） |
| 説明           | 任意                                                                                                                 |
| 初期内容       | 作成時のみ。空のデータベース / 既存データベースから複製                                                              |

#### 作成

- 空のデータベース: v1（編集中）を作り、スキーマを1つ作成する（PostgreSQL 18 は `public`。SQLite 3 はスキーマを持たない）。
- 既存データベースから複製: 同じプロダクトのデータベースの確定バージョンを選び、その設計を新しいデータベースの v1（編集中）として複製する。
  - オブジェクト・カラム・制約・インデックスのキーと、キーによる参照を引き継ぐ。保存行の ID は新しくする。キーはデータベースごとに扱うため、複製後は独立して編集できる。
  - v1 の作成元バージョンは NULL とし、共通カラムのセットは空で開始する（セットはバージョンの設計に含まれない）。
- 作成すると、v1 の設計画面を開く。

#### 名前の変更・削除

- データベース名と説明は変更できる。
- データベースを削除すると、配下のバージョン・設計とともに削除状態にし、保持期間（「リミット値」参照）が過ぎたら完全に削除する。確認は「共通ルール > 削除」参照。

#### バージョンの状態

| 状態 | 値                                   | 単位 |
| ---- | ------------------------------------ | ---- |
| 状態 | 編集中（デフォルト） / 仮確定 / 確定 | 共有 |

- 編集中 → 仮確定: 仮確定のチェック（下記）でエラーが0件のときにできる。メモを入力できる。
- 仮確定 → 編集中（編集に戻す）: いつでもできる。そのバージョンをビルド・マイグレーションした接続先があれば、「適用済みの接続先と設計がずれます」と警告し、確認してから戻す。
  - 自動ビルド・マイグレーションの実行中は、そのバージョンを編集に戻せない。実行終了後に戻す。
- 仮確定 → 確定: 条件なしでできる。確定ダイアログで接続先ごとの適用状況を表示する。確定すると、編集にも戻せない。確定するときに、続けて新しいバージョン（編集中）を作成できる。
- 1つのデータベースで、編集中または仮確定のバージョンは最新の1つだけ。最新が確定するまで、新しいバージョンは作れない。

#### 仮確定のチェック

- エラー（1件でもあれば仮確定できない）: DDL を生成できない設計。例: 主キーのないテーブル、参照先のない外部キー、構文・参照チェックに失敗したビュー、ターゲットの規則に合わない物理名。
- 警告（あっても仮確定できる）: 設計の不足。例: サイズ設計が未入力のテーブル、論理名・コメントのないオブジェクト・カラム、インデックスでカバーされていない外部キー。
- チェック結果と、直前の確定バージョンからの変更件数（追加・変更・削除）を表示する。

#### 設計の保存

- オブジェクト（スキーマ・テーブル・ビュー・シーケンス）ごとに「保存」ボタンで保存する。1つのオブジェクトへの編集（テーブルならカラム・制約・インデックス・サイズ設計）は画面上でまとめ、保存で1回だけ書き込む。
- 未保存の編集があるまま画面を離れるときは確認する。
- 保存ごとに操作履歴を1件記録する。同時更新はオブジェクト単位で判定する（「共通ルール > 同時更新」参照）。
- 1つのバージョンの設計（削除済みを除くオブジェクトの詳細）の合計サイズには上限がある（「リミット値」参照）。超える追加・保存はエラーにする。

#### サイズ設計の計算

- 時間・日・月の入力を年換算する。概算では年を365日、月を年の1/12とする。初期・1年後・3年後・5年後の件数は「初期件数＋（INSERT－DELETE）×年間単位数×経過年数」で、負の件数は0とする。保持期間を設定した場合は経過年数を保持期間で頭打ちにし、初期件数は基礎容量として残す。UPDATE は件数を増やさない。
- 型幅は固定長型のバイト数を用いる。可変長文字列は宣言長の半分＋4バイト、長さ未指定・バイナリ等は36バイト、numeric は16バイトを仮定する。NULL の割合、圧縮・TOAST は反映しない。
- PostgreSQL の行ヘッダー・NULL ビットマップ・8バイト境界・行ポインターを加え、fillfactor とページ丸めを反映する。SQLite は簡略化した行ヘッダーと型幅で計算する。索引は定義した索引と主キー・UNIQUE の自動索引を数え、列幅とエントリーの概算を用いる。部分索引の選択率・索引方式別の実容量は反映しない。
- ピーク書き込みは INSERT・UPDATE・DELETE の合計を秒換算してピーク係数を乗じる。不要タプルは PostgreSQL の単位あたり UPDATE＋DELETE、WAL は行・索引幅と操作数から概算する。SQLite の WAL は推定しない。結果は実測値ではなく容量計画の概算であり、推奨・注意は表示しない。

#### オブジェクトの削除

- 配下に削除されていないオブジェクトがあるスキーマは削除できない。先に配下を削除する。参照先を削除した場合は参照元を自動変更せず、仮確定チェックで参照の不足をエラーにする。

#### ビュー

- 定義（SELECT）は、保存時と仮確定のチェックで構文と参照（テーブル・カラム）を検証する。
- 出力カラムは、SELECT を解析して得た名前だけを表示する（型は表示しない）。
- PostgreSQL の構文は PostgreSQL 18 のパーサー、SQLite の構文・参照はメモリ上の SQLite エンジンで検証する。アプリの D1 や接続先 DB に入力された SQL を実行しない。
- ビューは読み取り専用の SELECT 一文とする。SELECT INTO・FOR UPDATE・更新する CTE・循環したビューを拒否する。PostgreSQL の静的参照検証はテーブル・ビュー、別名、JOIN、非再帰 CTE、サブクエリ、集合演算を対象とする。再帰 CTE、FROM の関数、NATURAL JOIN、JOIN 全体の別名は未対応として拒否する。関数・演算子の実在や型の適合は接続先での実行時に確認する。
- シーケンスの数値は精度を保つため API では十進整数の文字列にする。型の範囲、開始値・最小値・最大値・増分・キャッシュを検証する。
- PostgreSQL の物理名は引用識別子として生成する。文字数・バイト数と NUL 文字を検証し、予約語は引用して使用できる。

#### 一覧

- データベース一覧はデータベース名順、バージョン履歴は新しい順とする。
- オブジェクトはスキーマ名 → 種類（テーブル・ビュー・マテリアライズドビュー・シーケンス）→ 物理名の順とする。

#### 共通カラム

- データベースごとに、共通カラム（例: created_at・updated_at）のセットを定義できる。
- テーブルのカラム一覧で「共通カラム」を選ぶと、セットをまとめてテーブルに追加する。追加したあとは通常のカラムとして扱い、セットを変更しても追加済みのカラムは変わらない。

#### テーブル定義書

- 任意のバージョンを選んで PDF または Markdown で出力する。出力形式を選択できる。どちらもブラウザで生成し、ファイルとしてダウンロードする（サーバーには保存しない）。Markdown は UTF-8 の `.md` ファイルとする。
- 出力範囲: すべてのスキーマ、または選んだスキーマ。
- 出力内容（選択できる）: 表紙・改訂履歴、テーブル一覧、カラム定義、制約・インデックス、サイズ設計、ビュー・シーケンス、DDL（付録）、指定したバージョンとの改訂箇所の印。
- 出力範囲・出力内容・比較するバージョンは、PDF と Markdown で共通とする。Markdown は見出し・表で構成し、DDL は SQL のコードブロックにする。改訂箇所は追加・変更・削除の文字で示す。
- PDF の用紙: A4 横 / A4 縦。PDF のプレビューにはページ数を表示する。Markdown には用紙・ページ数を適用しない。
- 編集中のバージョンには、PDF では「ドラフト」の透かしを入れ、Markdown では冒頭に「ドラフト」と表示する。
- 定義書の取得 API は形式・用紙を受け取らず、状態・出力範囲・改訂箇所・定義・サイズ見積もりを共通 JSON で返す。付録 DDL を生成できない場合は、そのエラーを定義書データとともに返し、DDL を除いて出力できる。選択スキーマ外の参照先が必要な付録 DDL は、出力範囲を広げるか DDL を除く。

#### 新しいバージョン

- 作成元には、そのデータベースの確定バージョンを1つ選ぶ（通常は最新の確定バージョン）。
- 作成元の設計をすべて複製し、番号は最新の番号 ＋ 1 にする。

### ビルド・マイグレーション

- 仮確定・確定のバージョンから DDL スクリプト・差分スクリプトを出力する。
- ターゲットが PostgreSQL 18 で、データベース接続情報がある場合は、接続先データベースに自動でビルド・マイグレーションできる。

#### 出力

- DDL スクリプト: 仮確定または確定のバージョンを1つ選んで出力する。
- 差分スクリプト: 仮確定または確定のバージョンを2つ（更新前・更新後）選んで出力する。
- 出力したスクリプトはコピー・ダウンロードできる。保存はしない（「データ仕様 > Cloudflare R2」参照）。
- DDL スクリプトの出力オプション: CREATE SCHEMA を含める / COMMENT ON を含める / BEGIN・COMMIT で囲む / IF NOT EXISTS を付与 / バージョン管理テーブルを作成 / 既存を DROP ... CASCADE。
- 差分スクリプトの出力オプション: インデックスは CONCURRENTLY で作成 / 制約は NOT VALID ＋ VALIDATE で追加 / lock_timeout を設定 / 削除（DROP）を含める。
- オプションはターゲットに当てはまるものだけを表示する（SQLite 3 にない機能は表示しない）。
- 差分スクリプトでは、名前だけの変更は PostgreSQL の RENAME を使い、構造を変更するテーブルは一時表へデータを退避して再作成する。SQLite は変更するテーブルとその参照元を再作成する。カラムのキーでデータを対応づけ、生成列は再計算し、採番履歴を維持する。再作成対象・データ損失の可能性・トランザクション外の処理を応答に示す。
- DROP を除外した場合、削除を伴うオブジェクトの変更を適用せず、更新後の設計と一致しない可能性を警告する。この出力では適用済みバージョンを進めない。既存データが新しい型・制約に合わないと適用は失敗する。SQLite はコミット前の外部キー検査で不整合を検出するとロールバックする。

#### 自動ビルド・自動マイグレーション

- 対象: ターゲットが PostgreSQL 18 のプロダクトだけ。SQLite 3 は DDL スクリプト・差分スクリプトの出力だけを提供し、データベース接続情報も設定しない。
- 接続先: インターネットから接続できる PostgreSQL だけ。接続は TLS を必須とする。社内ネットワークなど、インターネットから接続できないデータベースには、出力したスクリプトを利用者が実行する。
- 接続先の TLS 証明書は、公的に信頼された認証局が発行したものに限る。自己署名の証明書や独自の認証局の証明書を使うデータベースには接続できない（Cloudflare Workers は証明書を必ず検証し、検証を無効にできないため）。その場合も、出力したスクリプトを利用者が実行する。
- 実行は非同期で行う。実行を受け付けたらすぐに応答し、画面を閉じても実行を続ける。進捗（手順ごとの件数・所要時間）と結果は画面で確認できる。
- 1つの接続先で同時に実行できるのは1件だけ。実行中の接続先には、次の実行を受け付けない。
- 接続先データベースには、適用済みのバージョンを記録するバージョン管理テーブル（`_dbcenter` スキーマ）を作る。
- 自動ビルド: 接続先データベースが空（バージョン管理テーブルもユーザーのオブジェクトもない）のときだけ実行できる。
- 自動マイグレーション: 実行前に次をチェックし、1つでも当てはまれば実行できない（出力した差分スクリプトを利用者が確認して実行する）。
  - 接続先の適用済みバージョンが、更新前のバージョンと一致しない。
  - 接続先に、設計にない変更（ドリフト）がある。
  - 差分にデータ損失（テーブル・カラムの削除など）を含む。
- 失敗したとき: トランザクション内の変更は自動でロールバックし、適用済みバージョンは更新しない。トランザクション外の処理（CREATE INDEX CONCURRENTLY など）で失敗した場合は、どこまで実行したかを実行ログに残して「失敗」とし、利用者が接続先を確認して対処する。自動で再実行はしない。
- 実行の結果（成功・失敗、実行ログ、実行した DDL）は履歴として残し、新しい順に表示する（「データ仕様 > deployments」参照）。
- データベース接続情報を削除しても実行履歴は残し、実行時の接続名に「（削除済み）」を付けて表示する。

### 履歴

- プロダクトで誰がいつ何をしたかを、参加者が確認できるようにする。

#### 記録する操作

- プロダクトの登録・変更・削除
- 参加者の招待・参加・除外・退出
- データベース接続情報の登録・変更・削除（パスワードの値は記録しない）
- データベースの作成・名前の変更・削除
- バージョンの作成・仮確定・編集に戻す・確定
- オブジェクト（スキーマ・テーブル・ビュー・シーケンス）の追加・変更・削除。変更内容の詳細は記録せず、バージョン間の差分で確認する。
- 自動ビルド・自動マイグレーションの実行と結果

#### 表示

- プロダクトごとに、新しい順で表示する。参加者は全員見られる。
- 保存期間は「リミット値」参照。過ぎた履歴は定期処理で削除する。プロダクトを完全削除したときは、そのプロダクトの履歴も削除する。
- 除外・退出したユーザーの名前はそのまま表示する。退会したユーザーは「退会したユーザー」と表示する。削除したデータベースの履歴は、名前をそのまま表示する。

#### 表示例

### データ保持・プライバシー

- 取得する個人情報は、Google アカウントの ID・メールアドレスと、利用者が入力したユーザー名だけとする。Google のプロフィール名・写真は保存しない（アイコンはユーザー名の頭文字を表示する）。
- 招待するときに入力されたメールアドレスは、招待の有効期限が過ぎたら定期処理で削除する。
- 退会したユーザーの Google アカウントの ID・メールアドレスは、退会時に削除する（「各論 > Googleでログイン」参照）。
- 削除したプロダクト・データベースは、保持期間（「リミット値」参照）が過ぎたら、配下の設計・実行履歴・実行した DDL・操作履歴とともに完全に削除する。
- 実行履歴と実行した DDL は、プロダクト・データベースを完全削除するまで残す。
- データベース接続情報のパスワードは暗号化して保存し、どの画面・API にも返さない。
- アクセスログ（リクエストの記録）は、ランタイムのログ機能に残す。
- 公開する文書: 利用規約、プライバシーポリシー（「共通ルール > 同意」参照）。

### データの取得とキャッシュ

D1 は読み取った行数で課金・制限されるため、読み取り行数をなるべく減らす。データはスコープ単位でまとめて取得して端末に保持し、変更がなければサーバーから取得し直さない。

#### スコープ

| スコープ       | 使う画面                                           | まとめて取得する内容                                                                                                                                   | リビジョン                |
| -------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------- |
| プロダクト一覧 | プロダクト一覧                                     | 参加しているすべてのプロダクト（プロダクト名・ターゲット・ロール・登録日・参加日）                                                                     | `users.products_revision` |
| プロダクト     | データベース一覧・プロダクト設定・ユーザー招待     | プロダクト、データベース接続情報（パスワードを除く）、参加者・仮登録、データベース一覧（最新・確定済みのバージョン、スキーマ数・テーブル数、更新日時） | `products.revision`       |
| データベース   | バージョン履歴・ビルド・マイグレーション           | すべてのバージョン、実行履歴、共通カラムのセット                                                                                                       | `databases.revision`      |
| バージョン     | 設計画面（オブジェクト一覧・各オブジェクトの詳細） | すべてのオブジェクト（詳細の JSON を含む）。差分取得する                                                                                               | `versions.revision`       |
| 操作履歴       | 操作履歴                                           | 新しい順にページ単位。2回目以降は前回より新しい行だけ                                                                                                  | なし（日時で続きを取得）  |

- スコープ内の画面の切り替え（例: テーブルから別のテーブルへ）は、端末のキャッシュから表示し、サーバーに問い合わせない。

#### リビジョン

- スコープごとに整数のリビジョンを持ち、スコープ内のデータを変更するたびに、データの変更と同じ一括処理（D1 の batch）で1増やす。
- 上位のスコープの一覧に表示する値も変わる場合は、上位のリビジョンも増やす。例: オブジェクトを追加すると、バージョンのリビジョンに加えて、データベース一覧のテーブル数・更新日時が変わるので、プロダクトのリビジョンも増やす。プロダクト名の変更・プロダクトの削除・参加者の増減では、関係するユーザー全員のプロダクト一覧のリビジョンを増やす。
- 取得するときは、端末が持っているリビジョンを送る。サーバーはリビジョンの1行だけを読み、一致すれば「変更なし」だけを返す（データの行は読まない）。
- バージョンのスコープは差分取得する。オブジェクトには最後に変更したときのバージョンのリビジョンを記録し（`objects.revision`）、端末のリビジョンより新しい行だけを返す。削除したオブジェクトは行を消さずに削除済みとして返し、端末のキャッシュからも消す。削除済みの行は確定時に物理削除し、それより前のリビジョンからの取得は全件取得に切り替える（`versions.compacted_revision`）。
- 登録・変更・削除の API は、変更後のデータと新しいリビジョンを返す。端末はそれでキャッシュを更新し、取得し直さない。

#### キャッシュ

- 取得したデータとリビジョンを、スコープごとに端末の IndexedDB に保存する。ユーザーごとに分けて保存し、ログアウト・退会したときは消す。
- アプリを開いたときも、まずキャッシュから表示する。
- フロントエンドは TanStack Query のキャッシュを IndexedDB に永続化し、自動の再取得（画面のフォーカス時・通信の再接続時・一定時間ごと）は使わない。

#### リビジョンを確認するタイミング

- スコープの画面を開いたとき: 最後に確認してから一定時間（「リミット値」参照）以内なら確認しない。過ぎていれば、リビジョンだけを確認する。
- アプリが前面に戻ったとき・通信が回復したとき: データは取得し直さない。表示中のスコープを最後に確認してから一定時間が過ぎていれば、リビジョンだけを確認する。複数のスコープは1回のリクエストでまとめて確認する。
- 保存が同時更新でエラーになったとき: そのスコープをすぐに差分取得する。
- 定期的な確認（ポーリング）はしない。例外は、自動ビルド・自動マイグレーションの実行中の進捗表示（実行履歴の1行だけを読む）。

#### サーバー側

- 一覧に表示する集計値（スキーマ数・テーブル数）と上限の判定に使う設計の合計サイズは versions に持ち、オブジェクトの追加・保存・削除のときに更新する。表示のたびに objects を数えない。
- 認証はセッションの主キー、権限は `product_members` の主キー（product_id, user_id）で、それぞれ1行だけ読んで判定する。
- すべての問い合わせは、インデックスで対象の行を絞る。主なインデックス: `product_members(user_id)`、`invitations(product_id)`、`invitations(passcode_hash)`、`connections(product_id)`、`databases(product_id)`、`versions(database_id)`、`objects(version_id, revision)`、`audit_logs(product_id, created_at)`、`deployments(connection_id, started_at)`、`passcode_failures(user_id, failed_at)`。

### データ仕様

仕様を満たす最小限のデータを保持する。導出できる値は都度集計する。

- 各テーブルの `id` は `crypto.randomUUID()` で生成する。
- 日時は UNIX エポックからのミリ秒（INTEGER）で保持する。
- データベース設計は、オブジェクト（スキーマ・テーブル・ビュー・シーケンス）を1行とし、その詳細を JSON で保持する。テーブルのカラム・制約・インデックス・サイズ設計は、テーブルの行の JSON に含める。ターゲットごとに設定項目が異なるため、項目ごとのカラムには分けない。
- オブジェクトとカラム・制約・インデックスには、バージョンをまたいで変わらないキーを持たせる。差分スクリプトは、2つのバージョンを同じキーどうしで比較して作る。名前を変えても同じキーのまま残るので、削除と追加ではなく名前の変更として扱える。
- 新しいバージョンは、作成元のバージョンのオブジェクトをすべて複製して作る。
- 次の値は保持せず、表示のたびに集計する: プロダクトの参加者数、最新バージョン・確定済みの最新バージョン、平均行サイズ・サイズの見積もり結果、接続先ごとの適用済みバージョン。スキーマ数・テーブル数・設計の合計サイズは読み取り行数を減らすため versions に持つ（「参照 > データの取得とキャッシュ」参照）。
- `revision` のカラムは、スコープのリビジョン（「参照 > データの取得とキャッシュ」参照）。初期値は1。

#### Cloudflare R2

- オブジェクトキー: `deployments/<deployment id>.sql`
- ビルド・マイグレーションで実行した DDL スクリプトを保存する。書き込みは実行時の1回だけで、上書きしない。プロダクトを完全削除するときに、あわせて削除する。
- テーブル定義書（PDF・Markdown）と、出力した DDL スクリプト・差分スクリプトは保存しない。定義書のファイルはブラウザで、スクリプトは要求のたびにバージョンから生成する。

#### DBの外で管理するデータ

- **データベース接続情報のパスワードの暗号鍵:** ランタイムのシークレットに保存する。
- **Google OAuth クライアント ID:** フロントエンドは `VITE_GOOGLE_WEB_CLIENT_ID`、バックエンドはランタイムのシークレットに設定する。
- **利用規約・プライバシーポリシーの本文と版:** コードに持つ。版が上がったら、ログイン時に再同意を求める（`users.terms_version` と比較する）。
- **ターゲット一覧:** コードの定数に持つ（「参照 > ターゲット一覧」参照）。
