# フロントエンド実装計画

`apps/frontend`（Vue 3 + Vuetify 4）に db-center の全画面を実装するための計画。仕様は `docs/spec.md`、規約は `AGENTS.md`・`apps/frontend/AGENTS.md` に従う。この計画と仕様が食い違う場合は仕様を正とし、実装で仕様を変えたら `docs/spec.md` も更新する。

## 1. 前提

### 1.1 画面デザイン

- 画面デザインは、ユーザーが配置した `docs/design/Rhg5wDkZzC4xarKvrA84bL.html`（PC全画面・プロダクト管理の各端末版）と `docs/design/4F2n9SHdSPPR3DMuqkSDaW.html`（データベース作成以降のスマホ・タブレット版）をブラウザーで表示して参照する。HTMLに埋め込まれたフォント・アイコン・CSSを含む実際の描画を、実装画面と同じ端末サイズで比較する。
- デザインの画面記号:

| 記号  | 内容                                                                 | 端末                   |
| ----- | -------------------------------------------------------------------- | ---------------------- |
| 1a–1i | ログイン・プロダクト管理・データベース一覧                           | PC（1280×800）         |
| 2a–2i | 同上                                                                 | タブレット（820×1180） |
| 3a–3i | 同上                                                                 | スマホ（390×844）      |
| 4a–4p | データベース作成・設計・バージョン・定義書・ビルド・マイグレーション | PC                     |
| 5a–5p | 同上                                                                 | タブレット             |
| 6a–6q | 同上（6f はオブジェクト一覧、6q は確定）                             | スマホ                 |

- デザインの共通部品: `AppBar`（ロゴ・パンくず・ヘルプ・ユーザー）、`DbHeader`（プロダクト／DB名・バージョン選択と状態・ナビゲーション「設計／ビルド／マイグレーション／バージョン履歴」・バージョン操作ボタン）、`SchemaTree`（オブジェクトツリーと変更件数）、`ObjHeader`（オブジェクト名・論理名・変更バッジ・タブ）、`ObjPath`（スマホの現在位置）。

### 1.2 デザインと仕様の食い違い（仕様に従う）

| デザイン                                                         | 実装                                                                       |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------- |
| サイズ設計の「推奨・注意」（4e・5e・6e）                         | 表示しない（「対象外」）                                                   |

### 1.3 デザインがない画面・操作

既存のデザインの部品（ダイアログ・カード・表）を流用して作る。

- 利用規約・プライバシーポリシー、再同意画面
- アカウントメニュー（ログアウト・退会）
- 参加者のロール変更・除外・オーナーの譲渡・退出の確認
- 操作履歴
- データベースの名前の変更・削除（2回確認）
- オブジェクト（スキーマ・テーブル・ビュー・シーケンス）の追加・削除（2回確認）
- テーブルの「テーブル設定」「DDL」タブ
- 共通カラムのセットの編集
- 「編集に戻す」の確認（適用済みの接続先がある場合の警告）
- 自動ビルド・マイグレーションの実行履歴の一覧
- オフライン表示、同時更新エラーの表示

## 2. 方針

### 2.1 UI

- デザインは「Material 系の部品（App Bar・Outlined 入力・Chip・Dialog）、低彩度のニュートラル＋インディゴ1色」。Vuetify の標準コンポーネントで組み、独自 CSS は最小にする。
- テーマ（`src/plugins/vuetify.ts`）にデザインの色を登録し、コンポーネントの既定値（`defaults`）で `variant: 'outlined'`・`density`・角丸を揃える。

| トークン         | 値                          | 用途                        |
| ---------------- | --------------------------- | --------------------------- |
| primary          | `#2F55D4`                   | 主ボタン・リンク・選択      |
| primary-darken-1 | `#2443B0`                   | ロールのチップの文字など    |
| background       | `#F4F5F7`                   | 画面の背景                  |
| surface          | `#FFFFFF`                   | カード・表                  |
| on-surface       | `#16191F`                   | 本文                        |
| 補助テキスト     | `#5B6270`                   | 見出しの補足・表のヘッダー  |
| 境界線           | `#E3E5EA` / `#CDD1D8`       | 表の罫線 / 入力欄・副ボタン |
| success          | `#2E9A62`（文字 `#1A6B43`） | 追加・成功                  |
| warning          | `#D99A00`（文字 `#7A4F00`） | 変更・警告                  |
| error            | `#C62F2F`（文字 `#A32424`） | 削除・データ損失・エラー    |

- アイコンはデザインの Material Symbols を、既存の `@mdi/font` の同等のアイコンに置き換える（例: `deployed_code` → `mdi-cube-outline`、`table_chart` → `mdi-table`）。
- 日付・日時は `2026/09/29`・`2026/09/29 10:21`（年なしは `9/29`）。デザインの `2026.10.10` 表記は使わない（「共通ルール > 日付・日時の表示」）。表示は `packages/utils` の日付関数を使う。
- 物理名・型・SQL・日時など等幅の値は等幅フォントで表示する（2.6 参照）。
- 操作できないボタンは非表示にする（無効表示にしない）。権限は `apps/backend` の権限表（`PERMISSIONS`）と同じ判定をフロントでも行う。判定関数は `packages/utils` に移して共有する（2.5）。

### 2.2 レスポンシブ

Vuetify の `useDisplay()` で3段階に分ける。

| 区分       | 幅                   | 構成                                                                                                                                   |
| ---------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| PC         | `md` 以上（960px〜） | 設計画面は左ツリー＋中央の一覧＋右の詳細パネル。ダイアログで登録・確認                                                                 |
| タブレット | `sm`（600–959px）    | 1カラム。ツリーは「オブジェクト」ボタンで開くドロワー、詳細パネルは一覧の下、ナビゲーションはヘッダー2段目のタブ                       |
| スマホ     | `xs`（〜599px）      | オブジェクト一覧を独立画面（6f）にし、詳細へ遷移。表はカード、主要操作は画面下部の固定バー、詳細編集はボトムシートまたはインライン展開 |

画面ごとに別コンポーネントを作らず、同じビューの中でレイアウトだけを切り替える。切り替えが大きい設計画面だけ、ツリー・詳細パネルの置き場所をレイアウト部品で切り替える。

### 2.3 サーバー状態とキャッシュ

「参照 > データの取得とキャッシュ」を TanStack Query で実装する。

- クエリはスコープ単位にする。

| スコープ       | クエリキー                 | API                                                                              |
| -------------- | -------------------------- | -------------------------------------------------------------------------------- |
| プロダクト一覧 | `['products']`             | `GET /api/products?revision=`                                                    |
| プロダクト     | `['product', productId]`   | `GET /api/products/:productId?revision=`                                         |
| データベース   | `['database', databaseId]` | `GET /api/products/:productId/databases/:databaseId?revision=`（実行履歴は差分） |
| バージョン     | `['version', versionId]`   | `GET /api/versions/:versionId?revision=`（オブジェクトは差分）                   |
| 操作履歴       | `['auditLogs', productId]` | `GET /api/products/:productId/audit-logs?before=&after=`（無限スクロール）       |

- `queryFn` はキャッシュにあるリビジョンを送り、`unchanged` ならキャッシュをそのまま返す。差分取得のスコープ（バージョン・実行履歴）は、返った行をキャッシュに合成し、削除済みの行を消す。合成は純粋関数（`src/cache/merge.ts` など）にしてテストする。
- 登録・変更・削除の応答（変更後のデータ＋ `revisions`）で `setQueryData` し、取得し直さない。上位スコープ（例: オブジェクト保存でプロダクトのテーブル数が変わる）は、応答の `revisions` を見て次回の確認で取得する。
- 自動の再取得は使わない: `refetchOnWindowFocus: false`・`refetchOnReconnect: false`・`refetchInterval` なし。`staleTime` は `LIMITS.revisionCheckMinutes`。
- アプリが前面に戻ったとき・通信が回復したときは、表示中のスコープのうち確認から一定時間過ぎたものを `POST /api/revisions/check` で1回にまとめて確認し、変わったものだけ取得する（`src/composables/useRevisionCheck.ts`）。
- 保存が `stale_update` になったら、そのスコープをすぐに取得し、「他のユーザーが更新しました。再読み込みしてください」を表示する。
- キャッシュは `@tanstack/query-persist-client-core` などの永続化で IndexedDB に保存する。保存キーはユーザー ID ごとに分け、ログアウト・退会で消す。アプリを開いたらまずキャッシュから表示する。
- 自動ビルド・マイグレーションの実行中だけ `GET /api/deployments/:deploymentId` をポーリングする（`refetchInterval` をその画面だけで使う）。

### 2.4 API 呼び出し

- Hono RPC クライアント（`src/api/client.ts`）を使い、型は `AppType` から得る。
- 共通のラッパー（`src/api/call.ts`）で、エラー応答 `{ error: { code, message, fields? } }` を `ApiError` に変換する。`401` はログイン画面へ、`consent_required` は再同意画面へ遷移する。`fields` はフォームの項目ごとのエラーに表示する。
- 既定のタイムアウト（3秒）は、DDL・差分スクリプト・定義書・ビューの検証・事前確認など時間がかかる API では延ばす（呼び出しごとに指定できるようにする）。

### 2.5 共有コード（`packages/utils`）

- 既にあるもの: `LIMITS`、`charLength`・`byteLength`、データベース名の検証、ターゲット（`TARGETS`）、サイズ見積もり（`estimateTableSize`）、日付、`TERMS_VERSION`。画面の入力チェック・サイズ設計の計算・表示にそのまま使う。
- 移すもの: 権限表と判定（`apps/backend/src/service/permission.ts` の `PERMISSIONS`・`allowedRoles` など、ランタイム非依存の部分）。バックエンドは移した先を import する。
- 移さないもの: zod スキーマ（バックエンドの検証）。フロントは入力の上限・必須だけを `LIMITS` でチェックし、詳しい検証はAPIの `fields` を表示する。

### 2.6 フォントと追加するライブラリ

ライブラリは、npm のダウンロード数が多く、ライセンスが MIT のものを選んだ（週間ダウンロード数は 2026/10/12 時点）。

| PDF の生成               | `jspdf`（MIT、約1,580万/週）＋ `jspdf-autotable`（MIT、約430万/週）                         | 表の自動改ページ・ヘッダーの繰り返しがあり、定義書の表に向く。`pdf-lib`（約1,780万/週）はダウンロード数は多いが、文字の配置しかできず表の組版を自作することになる。`pdfmake`（約290万/週）より利用が多い                                                                                           |

## 4. 画面ごとの実装

### 4.1 共通（App シェル）

- `AppBar`: ロゴ「db-center」、パンくず（プロダクト > …）、ユーザーのアイコン（ユーザー名の頭文字）とメニュー（ログアウト・退会・利用規約・プライバシーポリシー）。スマホは戻るボタン＋タイトル。
- 既存の「新しいバージョンがあります」スナックバー（`usePwaUpdate`）と通知ストアをそのまま使う。
- オフライン: `navigator.onLine` と `online`/`offline` イベントで「オフラインです」を表示し、登録・変更・削除・出力・ビルド・マイグレーションのボタンを押せなくする（読み取り専用）。
- サンプル（`HomeView`・`SampleView`・`useSampleQuery`）はフェーズ0で削除した。

### 4.2 ログイン・同意（1a 1b、2a 2b、3a 3b）

- STEP 1: 公式の Google ボタン。`VITE_GOOGLE_WEB_CLIENT_ID` が未設定なら、公式に似せた無効の `v-btn` を出す。開発時（`import.meta.env.DEV`）だけ開発用ログインを表示する（`POST /api/auth/dev-login`）。
- ID トークンを `POST /api/auth/google` に送る。登録済みならプロダクト一覧へ、`registration_required` なら STEP 2。
- STEP 2: Google アカウント（メール）、ユーザー名（必須、`LIMITS.userNameMaxLength`）、「利用規約 と プライバシーポリシー に同意する」。チェックするまで「登録して始める」を押せない。`POST /api/auth/register`（`TERMS_VERSION` を送る）。規約へのリンクは新しいタブで開く。
- 再同意: `GET /api/auth/me` が `consentRequired` なら `/consent` で同意させる（`POST /api/auth/consent`）。
- 利用規約・プライバシーポリシーの本文は `src/legal/documents.ts` に置き、運営者名・連絡先は `VITE_OPERATOR_NAME`・`VITE_CONTACT_EMAIL` から埋め込む（`docs/agents/public-app.md`）。
- 退会: 確認ダイアログ → `DELETE /api/auth/me` → キャッシュを消してログイン画面へ。オーナーのプロダクトがあるとエラーを表示する。

### 4.3 プロダクト一覧（1c 2c 3c）

- 見出し「プロダクト」「参加中 n / 20」（`LIMITS.productsPerUser`）。「プロダクトに参加」「プロダクトを追加」。
- 表: プロダクト名・ターゲット・ロール（チップ）・登録日・参加日・編集ボタン（オーナー・マネージャーのみ）。並びはプロダクト名順。行の選択でデータベース一覧へ。
- スマホはカードにし、「参加する」「追加する」を下部の固定バーに置く。

### 4.4 プロダクト登録・編集・削除（1d 1e 1f）

- 登録: プロダクト名（必須、`LIMITS.productNameMaxLength`）、ターゲット（`TARGETS` から選択、登録後は変更不可と表示）、データベース接続情報（0…N）。
- 接続情報の行: 接続名・接続文字列・パスワード。ターゲットが SQLite 3 のときは接続情報の欄を出さない。仕様の説明文（「インターネットから接続でき…」）を表示する。上限は `LIMITS.connectionsPerProduct`。
- 登録は `POST /api/products` のあと、接続情報ごとに `POST /api/products/:productId/connections`。
- 編集: プロダクト名（`PATCH /api/products/:productId`）、ターゲットは参照のみ、接続情報の追加・変更・削除（`POST`・`PATCH`・`DELETE …/connections/:connectionId`）とドラッグでの並べ替え（SortableJS、`PUT …/connections/order`）。パスワードは「設定済み」と表示し、変更する場合だけ入力する。
- 保存は変更のあった項目だけ送り、各 API に `expectedUpdatedAt` を付ける。
- 削除（オーナーのみ）: 1回目「プロダクトを削除しますか？」（データベース件数・参加者数）→ 2回目でプロダクト名の入力が一致したら「完全に削除する」（`DELETE /api/products/:productId`）。

### 4.5 招待・参加（1g 1h）

- 招待: Google アカウントとユーザー種別の行を複数入力（「行を追加」）。マネージャーはメンバーだけ招待できる（選択肢をメンバーだけにする）。「招待コードを表示する」で `POST /api/products/:productId/invitations` → 8桁のコードを表示し、コピー（スマホは共有も）。有効期限を表示する。
- 参加者一覧: オーナー → マネージャー → メンバー → 仮登録の順。仮登録の行はパスコードを再表示できる（`POST …/invitations/:invitationId/passcode`）。
- 参加者の行メニュー（デザインなし）: ロール変更（`PATCH …/members/:userId`）、除外（`DELETE …/members/:userId`）、オーナーの譲渡（`POST …/transfer-owner`）。表示は権限表に従い、除外・譲渡は確認ダイアログを出す。
- 退出: データベース一覧の「プロダクトから退出」→ 確認 → `POST /api/products/:productId/leave`。オーナーには出さない。
- パスコード入力: 8桁（英数字・大文字小文字を区別しない・貼り付け可）。8文字入力すると「参加する」を押せる。`POST /api/invitations/join`。失敗時は仕様の文言を表示し、入力回数の上限に達したらそのエラーを表示する。

### 4.6 データベース一覧（1i 2i 3i）

- 見出し: プロダクト名・自分のロール。データベースの表: データベース名（スキーマ数・テーブル数）、最新バージョンと状態、確定済みバージョン、更新日時、行メニュー（名前の変更・削除はオーナー・マネージャーのみ）。並びはデータベース名順。
- サイドパネル「プロダクト情報」: ターゲット、接続情報、設定（オーナー・マネージャー）、参加者 n / 10（`LIMITS.membersPerProduct`）と「招待する」、操作履歴へのリンク、「プロダクトから退出」。タブレットは上部の2カード、スマホは下部の固定バー（設定・招待・DB作成）。
- データベース作成（4a、ダイアログ）: データベース名（`packages/utils` の検証）、説明（`LIMITS.databaseDescriptionMaxLength`）、初期内容（空 / 既存の確定バージョンから複製）。`POST /api/products/:productId/databases` のあと v1 の設計画面へ。
- 名前の変更（`PATCH …/databases/:databaseId`）・削除（2回確認、`DELETE …/databases/:databaseId`）。

### 4.7 操作履歴（デザインなし）

- プロダクトごとに新しい順のリスト。表示は「山田 太郎 が ec_main v4 を仮確定」の形（「各論 > 履歴 > 表示例」）。
- 下へスクロールで `before` を付けて前のページ（`LIMITS.auditLogPageSize` 件ずつ）、開き直したら `after` で新しい行だけ取得する（`useInfiniteQuery`）。

### 4.8 データベース設計（4b–4h 4p、5b–5h 5p、6b–6h 6p）

#### ヘッダー（DbHeader）

- プロダクト名・ターゲット、データベース名、バージョン選択（状態のチップ: 編集中・仮確定・確定）、ナビゲーション「設計・ビルド・マイグレーション・バージョン履歴」。
- バージョン操作: 定義書 PDF、仮確定（編集中）、編集に戻す・確定（仮確定。オーナー・マネージャー）、新しいバージョン（最新が確定。オーナー・マネージャー）。
- 編集中以外のバージョンでは、設計の入力をすべて読み取り専用にする。

#### オブジェクトツリー（SchemaTree）

- スキーマ → 種類（テーブル・ビュー・マテリアライズドビュー・シーケンス）→ 物理名の順。検索欄、追加ボタン（スキーマ・テーブル・ビュー・シーケンス）。
- 作成元バージョン（直前の確定バージョン）との比較で、オブジェクトに A（追加）・M（変更）を付け、下部に「v3 からの変更 A n・M n・D n」を出す。比較はキャッシュした作成元バージョンのオブジェクトと `object_key` で照合し、詳細 JSON の違いで判定する（純粋関数にしてテスト）。カラム・制約・インデックスの行の追加・変更の印も同じ方法で付ける。
- SQLite 3 はスキーマを持たないため、種類ごとの一覧だけにする。シーケンス・マテリアライズドビューは出さない。

#### スキーマ（4f）

- 物理名・論理名・所有者ロール・コメント。配下のオブジェクトの表（種別・物理名・論理名・カラム数・インデックス数・5年後サイズ・変更内容）と合計。
- 削除は、配下にオブジェクトがなければ2回確認で削除できる。あれば理由を表示して削除させない。

#### テーブル（ObjHeader とタブ）

- ヘッダー: 物理名・論理名・変更バッジ（SQLite 3 は STRICT）、複製・メニュー（削除）。タブ: カラム（件数）・制約（件数）・インデックス（件数）・サイズ設計・テーブル設定・DDL。
- カラム（4b）: 表（#・PK・物理名・論理名・データ型・NN・デフォルト・制約の略号）、「カラムを追加」「共通カラム」、ドラッグで並べ替え（SortableJS。スマホは長押し）、平均行サイズ（`estimateColumnBytes`）。詳細パネル: 物理名・論理名・データ型（長さ・精度）・NOT NULL・デフォルト値・値の生成（なし／IDENTITY／生成列）・コメント・詳細（照合順序・ストレージ・圧縮。PostgreSQL のみ）・削除。作成元からの変更（例: `v3: varchar(16) から変更`）を表示する。上限は `LIMITS.columnsPerTable`。
- 制約（4c）: 表（種別・制約名・対象カラム・定義）、「制約を追加」（PRIMARY KEY・FOREIGN KEY・UNIQUE・CHECK・EXCLUDE。SQLite 3 は EXCLUDE なし）。外部キーの詳細: カラム → 参照先テーブル・カラム、ON DELETE・ON UPDATE・MATCH・遅延評価、参照元をカバーするインデックスの有無。
- インデックス（4d）: 表（名前・方式・キー列／条件・UNIQUE・5年後サイズ）と合計。制約による自動作成の行は読み取り専用。詳細: 方式（PostgreSQL 6種、SQLite 3 は B-tree のみ）、キー列・式（順序・NULLS・演算子クラス、並べ替え）、INCLUDE、部分条件、UNIQUE、fillfactor、カバーする FK。
- サイズ設計（4e）: 平均行サイズ（自動）、初期件数、時間単位（時・日・月）、INSERT・UPDATE・DELETE、ピーク係数、保持期間、メモ。結果の表（初期・1年後・3年後・5年後の件数・テーブル・インデックス・合計）とピーク時書き込み・不要タプル・WAL。計算は `estimateTableSize`。推奨・注意は出さない。
- テーブル設定（デザインなし）: コメント、fillfactor（PostgreSQL）、STRICT・WITHOUT ROWID（SQLite 3、4p）。
- DDL（デザインなし）: そのテーブルの DDL を表示・コピーする（`POST /api/versions/:versionId/ddl` の結果からテーブルの文を抜き出す）。
- 共通カラム: 「共通カラム」でデータベースの共通カラムのセットをテーブルに追加する。セットの編集はダイアログ（`PUT …/databases/:databaseId/common-columns`）。

#### シーケンス（4g、PostgreSQL のみ）

- 物理名・論理名・データ型（smallint・integer・bigint）・開始値・増分・キャッシュ・最小値・最大値・循環・所有カラム・コメント。数値は十進の文字列で扱う。使用箇所と CREATE SEQUENCE のプレビューを表示する。

#### ビュー（4h）

- ビュー / マテリアライズドビュー（PostgreSQL のみ）の切り替え、定義（SELECT。CodeMirror 6 の SQL エディター、行番号・ハイライト付き）、「検証」（保存時と同じチェックを API で実行）、オプション（security_invoker・security_barrier・CHECK OPTION、マテビューは WITH DATA）、依存オブジェクト、出力カラム（名前のみ）、コメント。スマホは「全画面で編集」。

#### 保存

- 1つのオブジェクトへの編集は画面上でまとめ（オブジェクト単位のフォーム状態）、「保存」で1回だけ送る。新規は `POST /api/versions/:versionId/objects`、更新は `PUT …/objects/:objectKey`（`expectedUpdatedAt`）、削除は `DELETE …/objects/:objectKey`（物理名の確認入力）。
- 未保存の編集があるオブジェクトから離れるときは確認する（別オブジェクトへの切り替えも含む）。
- 応答でバージョンのキャッシュを更新する。`stale_update` は 2.3 のとおり。保存のエラーの `fields` を該当する行・項目に表示する。

### 4.9 バージョン（4i 4j、6i 6q 6j）

- 仮確定（ダイアログ）: 開くと `POST /api/versions/:versionId/validate` を実行し、エラー・警告の件数と一覧（「開く」で該当オブジェクトへ）、直前の確定バージョンからの変更件数（追加・変更・削除）を表示する。エラーが0件のときだけ「仮確定する」。メモを入力できる（`LIMITS.commentMaxLength`）。`POST …/provisional`。
- 編集に戻す: 確認ダイアログ。適用済みの接続先がある場合は「適用済みの接続先と設計がずれます」を表示して `acknowledgeApplied: true` で送る（`POST …/revert`）。実行中のデプロイがあるとエラーを表示する。
- 確定（ダイアログ）: `POST …/finalize-preview` で接続先ごとの適用状況（同じ設計の適用済み・別の設計・未適用・接続状態不明）を表示する。「確定後、続けて v(n+1)（編集中）を作成する」。`POST …/finalize`（`createNext`）。
- バージョン履歴: 新しい順の表（バージョン・状態・作成元・メモ・仮確定・確定・適用環境）、行から差分（マイグレーション画面へ）・定義書出力。
- 新しいバージョン（ダイアログ）: 作成元の確定バージョンを選ぶ（最新が既定）。`POST …/databases/:databaseId/versions` のあと新しいバージョンの設計へ。

### 4.10 テーブル定義書（4k 5k 6k）

- バージョン、出力形式（PDF / Markdown）、出力範囲（すべて / 選んだスキーマ）、出力内容（表紙・改訂履歴、テーブル一覧、カラム定義、制約・インデックス、サイズ設計、ビュー・シーケンス、DDL 付録、比較するバージョンとの改訂箇所の印）、用紙（PDF のみ: A4 横 / A4 縦）、ファイル名。
- `POST /api/versions/:versionId/definition-export` の JSON から、ブラウザで PDF（jsPDF ＋ jspdf-autotable、フォントは Noto Sans JP の TTF）または Markdown を生成してダウンロードする。PDF はプレビューとページ数（jsPDF のページ数）を表示する。編集中のバージョンは PDF に「ドラフト」の透かし、Markdown の冒頭に「ドラフト」。
- 付録 DDL を生成できないときは、エラーを表示して DDL を除いて出力できるようにする。
- 生成処理（JSON → Markdown 文字列、JSON → PDF 定義）は DOM に依存しない関数にしてテストする。

### 4.11 ビルド（4l 4m）

- 対象バージョン（仮確定・確定のみ）、実行方法（DDL を出力 / 自動ビルド）。自動ビルドはターゲットが PostgreSQL 18 で接続情報があり、権限があるときだけ出す。
- DDL を出力: オプション（CREATE SCHEMA・COMMENT ON・BEGIN/COMMIT・IF NOT EXISTS・バージョン管理テーブル・DROP … CASCADE。ターゲットに当てはまるものだけ）。`POST /api/versions/:versionId/ddl` の結果を等幅で表示し、行数・コピー・ダウンロード（`.sql`）。スマホは折りたたみのプレビューと「全文を表示」。
- 自動ビルド: 接続先を選ぶと事前確認（`POST /api/connections/:connectionId/deployment-preview`）の結果（空のDBか、適用済みバージョン、設定不足など）を表示する。実行は冪等キー（`crypto.randomUUID()`、再送でも同じキー）を付けて `POST …/deployments`（202）。
- 実行中・実行後: 手順ごとの件数・所要時間・状態をポーリングで表示する。画面を閉じても実行は続く旨を表示する。結果（成功・失敗・失敗（結果不明））、実行ログと実行した DDL（`GET /api/deployments/:deploymentId/script`）のダウンロード。

### 4.12 マイグレーション（4n 4o）

- 更新前・更新後のバージョン（仮確定・確定）、実行方法（更新用 DDL を出力 / 自動マイグレーション）。
- 更新用 DDL: `POST /api/databases/:databaseId/migration-script`。差分の一覧（+ 追加・~ 変更・− 削除、注記: 書き換えなし・ロック短縮・トランザクション外・再作成・データ損失）、件数の集計、生成オプション（CONCURRENTLY・NOT VALID ＋ VALIDATE・lock_timeout・DROP を含める。SQLite 3 にないものは出さない）、DROP を除外したときの警告、スクリプトの表示・コピー・ダウンロード。
- 自動マイグレーション（実行確認ダイアログ）: 事前確認の結果（接続・適用済みバージョンの一致・ドリフト・データ損失）を表示し、1つでも当てはまれば実行させず、更新用 DDL の出力を案内する。実行と進捗はビルドと同じ。

### 4.13 実行履歴（デザインなし）

- バージョン履歴の画面に、データベースの実行履歴（新しい順）を表示する: 種類・接続名（削除済みは「（削除済み）」）・バージョン・状態・実行者・開始・終了。行から実行ログ・実行した DDL を見られる。データはデータベースのスコープ（差分取得）から得る。

## 8. テスト

テストは Node で動かす（DOM なし）。コンポーネントはマウントしない。

- ルーター: 各パスが想定のルート名に解決されること（`router.resolve`）。ガードの判定は関数に分けてテストする。
- コンポーザブル: API クライアントをモックし、`unchanged`・`full`・差分の各応答でキャッシュが正しくなること、変更の応答で `setQueryData` されること。
- 純粋関数: 差分の合成、作成元との比較、フォーム ⇔ API 入力の変換、権限、定義書の Markdown 生成、日付表示。
- ストア: 認証ストア（ログイン・ログアウトでキャッシュが消えること）、通知ストア。
